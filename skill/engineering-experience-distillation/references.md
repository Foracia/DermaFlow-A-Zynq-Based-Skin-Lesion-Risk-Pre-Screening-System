# 工程经验蒸馏与 Skill 迭代：来源与演进

## 底稿与压缩原则

本 Skill 来自项目实际使用的 884 行 Engineering Experience Distiller。收束时保留其高价值机制：材料路由、证据标签、失败链、外部归属、禁止捏造和轻量输出；将重复解释、长示例和成熟度说明移出可执行正文。

目标不是把规范缩短后原样陈列，而是让另一个 Agent 在会话结束时能直接执行“筛选—核查—分流—抽象—验证—归档”。

## 最终收束材料时的人机协同双任务真实应用

| 处理 | 实际内容 | 理由 |
|---|---|---|
| 保留为 Skill | Overlay 分阶段启动、HLS 分层数值验证、资源联合评价、受控性能测量、量化参考锁定、经验蒸馏、工程交接 | 都能描述一类任务，并有明确验证与失效边界 |
| 保留为报告证据 | 具体模型哈希、寄存器地址、各轮数字、温度阈值、样本量和失败日志 | 项目事实重要，但不应全部塞入通用流程 |
| 合并 | 多轮 HLS／资源优化经验 | 只抽取能改变后续操作的规则，避免 42 轮流水账 |
| 排除 | 常规确认、重复讨论、无工程影响的建议、凭据和个人信息 | 路由 `NONE` 或发布风险 |
| 降级表述 | 早期工作流角色、未系统留存的提示词、独立复验和跨项目通用性 | 没有直接证据时保持设计、复盘或当前记录身份 |

## 成熟度纠正

早期材料使用 L0～L4 描述知识证据覆盖。当前交付保留它作为可选的证据描述，但不再把 L4 当作正式 Skill 的资格门槛。复用性和实际有效性是核心；多轮使用与失败修订是增强 Skill 的方式，而不是 Skill 存在的前提。

## 与其他六个 Skill 的关系

本 Skill 是元流程，负责从工程材料中生成和维护其他 Skill。它不替代具体技术验证；技术结论仍由对应的仿真、实现、板测或统计证据支持。

## 来源

- 用户提供的 Engineering Experience Distiller，项目研发中实际用于 `quantization/experience/` 的材料整理。
- `quantization/experience/README.md`：既有 REPORT／SKILL／BOTH 材料和历史状态管理。
- 最终收束材料时的七个 Skill 与协作案例：参与人机协同的执行 Agent 的真实应用对象。

## 外部归属

conversation mining、retrospective reflection、Skill library 和 progressive disclosure 等属于通用思想。本交付的可主张贡献是面向本竞赛 FPGA／PYNQ 证据链的独立适配、具体流程和实际材料组织。
