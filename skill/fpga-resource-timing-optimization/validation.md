# FPGA 资源—时序—延迟协同优化：验证记录

## RED：历史失败基线

**场景**：Round42 首种共享 `q` 的 ROM 写法达到 49,152 次仿真一致，且报告为 0 BRAM。若优化目标只有“减少 BRAM”，极易误判为最佳候选。

**失败识别**：同报告同时给出 7,730 LUT，说明存储被转成逻辑，而非无成本消除。数值正确和单项资源下降均不足以通过联合评价门。

**由此形成的测试要求**：Skill 必须读取完整资源表、确认识别真实 primitive，并在完整计算链和配对物理实现后才允许保留候选。

来源：`HISTORICAL_ARTIFACT`，Round42。

## GREEN：桌面应用检查

**测试输入**：Round42 两种写法的数值、资源、时序和完整链结果。

**最终收束材料时参与人机协同的执行 Agent 应用结果**：

- 否决首种“49,152 次一致＋0 BRAM＋7,730 LUT”候选，没有把 0 BRAM 单独写成成功；
- 对第二种候选同时保留 BRAM 65→54.5 Tile、LUT 4,177→4,206、DSP 不变、setup 1.476→1.251 ns 和 hold 0.032→0.009 ns；
- 核对四帧原码、每帧周期、输入词和背压一致后，才接受“未增加 RTL 周期”；
- 将结论限定为 Round41 来源 CNN＋原 AXI 包装，不生成新的完整视频整机资源值，不声称新候选已经上板。

**结论**：`PASS_WITH_NOTES`。Skill 能识别资源迁移并阻止单项指标误判。该检查由最终收束材料时参与人机协同的执行 Agent 基于冻结材料完成，不是独立 Agent 压力测试或新硬件实验。

## REFACTOR：修订与未覆盖范围

应用检查后把“实际 primitive”和“当前部署完整链”从建议提升为独立门。当前只证明本项目、该 ROM 和该工具条件下的候选有效；其他存储结构、工具版本和整机集成必须重新验证。
