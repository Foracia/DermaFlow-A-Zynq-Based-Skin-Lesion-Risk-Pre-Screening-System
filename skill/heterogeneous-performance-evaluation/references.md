# 异构系统性能测量与受控对照：来源与演进

## 初测为什么不能直接形成加速比

SYS-Round01 的 ARM 初测显示质量统计和 PNG 保存存在明显改善趋势，但两轮图像不同、组数不等，baseline 还出现较高 fsync 等待。移动目标会改变质量拒绝次数和 PNG 工作量，因此这些结果被保留为非受控观察，而不是正式优化因果结论。

## 固定输入受控复测

后续工具冻结 4 张回收照片，两个实现在每种模式各预热 1 次，以 5 个 ABBA 块获得每实现每模式 10 次正式归档。共 40 次正式、4 次预热；归档顺序、输入身份、原始记录和重新计算汇总均通过核对。

| 同边界指标 | baseline | optimized | 必须保留的解释 |
|---|---:|---:|---|
| 质量统计 | 约 330—332 ms/张 | 约 199 ms/张 | 约下降 40% |
| PNG 编码 | 约 1,286—1,353 ms/张 | 约 223—231 ms/张 | 约下降 83% |
| 普通完整归档中位数 | 1,564 ms | 530 ms | 典型耗时改善 |
| 融合完整归档中位数 | 5,133 ms | 1,458 ms | 典型耗时改善 |
| 普通完整归档均值 | 1,585 ms | 946 ms | 与 P95 一起阅读 |
| 融合完整归档均值 | 5,743 ms | 2,252 ms | 与 P95 一起阅读 |
| 普通完整归档 P95 | 1,753 ms | 2,697 ms | **尾部变差，不得省略** |

固定照片的 PNG 体积增加约 16.60%／13.61%，说明编码耗时和文件大小是不同折中。未分解的约 1.56—2.03 秒尖峰不能仅凭差值归因到 JSON fsync。

## 计时边界示例

最终 PL 批处理中，硬件事务均值约 48.86 ms，而标准化输入到 logits 均值约 69.50 ms。两者都是有效数据，但边界不同，不能与其他 CPU 历史结果随意拼接加速比。

首屏、质量复核、保存和完整归档也发生在不同时间区间。保存变快不必然使某个首屏指标同比变快。
