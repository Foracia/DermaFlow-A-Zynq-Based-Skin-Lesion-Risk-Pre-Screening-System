# 案例 04：性能结果审查历史案例回放

**记录类型**：`NEW_COLLABORATION_RECORD`＋`HISTORICAL_ARTIFACT`  
**对应 Skill**：[异构系统性能测量与受控对照](../../../skill/heterogeneous-performance-evaluation/SKILL.md)

## 1. 回放任务提示

> 审查 SYS-Round01 初测、固定输入复测和 PL 批处理计时。指出哪些结果可用于正式对照，哪些只能作为趋势；同时报告中位数、均值、P95 和计时边界，不得把归档、首屏、硬件事务或视频吞吐混报。

这是最终收束材料时的人机协同记录中的桌面回放任务，不是开发期原始提示词。

## 2. 输入证据

- 初测使用不同实拍输入，组数不等且有 I/O 尖峰。
- 受控复测冻结 4 张照片，每实现每模式预热 1 次、5 个 ABBA 块、10 次正式归档。
- 普通／融合完整归档中位数 1,564→530 ms、5,133→1,458 ms；普通 P95 却由 1,753→2,697 ms。
- PL 硬件事务均值约 48.86 ms，标准化输入到 logits 均值约 69.50 ms，边界不同。

详细数字见 [性能测量参考资料](../../../skill/heterogeneous-performance-evaluation/references.md)。

## 3. 模型输出摘要

**以下为最终收束材料时的人机协同记录中的模型输出摘要，不是逐字原始回答。**

初测只能作为非受控改善趋势；正式对照采用固定输入、预热排除和 ABBA 复测。优化版典型归档耗时下降，但普通模式 P95 变差必须与均值和中位数同时报告。约 48.86 ms 与约 69.50 ms 不得与其他边界的历史 CPU 数字拼接加速比。离板归档测量也不能外推为首屏、视频吞吐或实时保证。

## 4. 工具反馈与修正

受控复测没有简单“证明初测所有结论”：它支持典型耗时改善，同时暴露尾部退化。由此 Skill 从“固定输入再测”进一步修订为“分布和原始行必须一起审查”。

总耗时减去已测组件后的差值只称未分解余量，不直接命名为 fsync 或某个未测函数。

## 5. 验证

[validation.md](../../../skill/heterogeneous-performance-evaluation/validation.md) 给出 `PASS_WITH_NOTES`：最终收束材料时参与人机协同的执行 Agent 能识别输入、边界和尾部问题，但没有新增性能测量或独立审查。

## 6. 最终可交付结论

可写“固定输入受控复测支持质量统计、PNG 编码和典型归档耗时改善，同时普通模式 P95 变差，后续仍需分解尾部来源”。不可只写“归档加速约三倍且实时性能稳定”。
