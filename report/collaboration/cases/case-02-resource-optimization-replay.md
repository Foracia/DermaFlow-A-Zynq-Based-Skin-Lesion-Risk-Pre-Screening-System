# 案例 02：资源优化历史案例

**记录类型**：`NEW_COLLABORATION_RECORD`＋`HISTORICAL_ARTIFACT`  
**对应 Skill**：[FPGA 资源—时序—延迟协同优化](../../../skill/fpga-resource-timing-optimization/SKILL.md)

## 1. 回放任务提示

> 依据 Round42 冻结材料，比较两种 Conv3 ROM 写法。判断哪些候选可以保留，并分别给出数值、真实资源、时序、完整计算链和整机／板端结论；不得因单项 BRAM 下降就宣布优化成功。

这是最终收束材料时的人机协同记录中的回放任务定义，不是开发期原始提示词。

## 2. 输入证据

- 首种共享 `q` 写法：49,152 次仿真一致，但综合为 7,730 LUT、0 BRAM。
- 第二种注册化分 bank：计算链 BRAM 65→54.5 Tile，Conv3 29→18.5 Tile；LUT 4,177→4,206，DSP 40 不变。
- setup 1.476→1.251 ns，hold 0.032→0.009 ns，均仍为正。
- 49,152 次 ROM 对照及四帧原码、周期、输入词和背压一致。
- 完整视频整机重新实现与新候选板测未做。

主要来源：[资源优化参考资料](../../../skill/fpga-resource-timing-optimization/references.md)。

## 3. 模型输出摘要

“首种候选应否决：49,152 次一致只通过数值门，0 BRAM 与 7,730 LUT 同时出现表明资源迁移。第二种候选可以保留为当前 CNN＋原 AXI 包装下的有效局部／完整计算链候选，但必须同时列出 LUT 小增、setup／hold 余量变化和完整链回归。不能生成新的整机资源值，也不能声称已上板。”

## 4. 工具反馈如何改变流程

历史综合报告提供了比“仿真一致”更强的反证，使首种候选被否决。后续配对实现和完整链结果又证明第二种候选不是同一种资源迁移陷阱。

本案例不虚构“模型曾推荐首种写法”的历史对话；RED 是用真实失败构造的反事实测试，GREEN 是最终收束材料时参与人机协同的执行 Agent 按 Skill 作出的实际审查。

## 5. Skill 修订与验证

- 将“检查真实 primitive”设为独立门，不信 `rom_style` 或目标指标 alone。
- 将“当前部署完整计算链回归”设为局部收益进入系统预算前的必要条件。
- 保留失败候选和完整资源表，不只展示成功候选。

结果见 [validation.md](../../../skill/fpga-resource-timing-optimization/validation.md)：`PASS_WITH_NOTES`，最终收束材料时参与人机协同的执行 Agent 桌面检查，不是独立复验或新硬件实验。

## 6. 最终可交付结论

可写“Round42 通过失败否决、数值等价、真实映射和配对物理实现，保留了未增加 RTL 周期的 ROM 分 bank 候选”。不可写“新完整视频整机已部署且资源下降同样幅度”。
