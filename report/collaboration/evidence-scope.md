# 协作证据范围与真实性声明

## 目的

本材料包同时保存 Skill、代表性大模型协作案例及其工程证据。为避免把事后整理误读为开发阶段原始记录，所有内容按以下来源类别理解。

| 标记 | 含义 | 可以证明 | 不能证明 |
|---|---|---|---|
| `HISTORICAL_ARTIFACT` | 项目开发期间已经存在的源码、报告、日志、设计文档、交接材料和版本记录 | 工程决策、实验结果、失败与修正、产物身份 | 当时具体使用了哪条提示词或哪段模型回答 |
| `RETROSPECTIVE_RECONSTRUCTION` | 项目完成后依据历史档案与团队讨论形成的流程复盘 | 对既往工程方法和协作模式的概括 | 逐字历史对话、当时已存在某个 Skill 或完整实施某个工作流 |
| `NEW_COLLABORATION_RECORD` | 最终收束材料时真实发生的人机协同提问、模型回答、人工纠正、材料回放与修订 | 最终收束材料时的 Skill 设计和应用过程、人工反馈驱动的纠错、验证方式 | 项目早期开发阶段的原始 Agent 使用情况 |

## 已知记录缺口

项目开发阶段未系统导出全部提示词、模型原始回答、模型快照或 Agent 运行日志。历史工程档案不会因此被丢弃，但也不能被包装成完整聊天记录。

早期调研中的任务包、Plan／Act、独立验证者、审批门和模型分工属于工作流设计依据。只有被历史材料或最终收束材料时的人机协同记录直接支持的部分，才表述为实际使用；其余表述为设计、收束阶段采用或后续建议。

## 最终收束材料时补充的人机协同证据

最终收束材料时的人机协同记录采用两种可核查方式：

1. **真实讨论记录**：保存团队在 Skill 目标、成熟度和交付边界上的实际提问、模型回答、人工纠正与设计修订。
2. **历史案例桌面回放**：向模型提供冻结的历史材料，让模型依据 Skill 做诊断或审查，再与后续真实实验结果对照。回放由同一执行 Agent 在最终收束材料时的人机协同过程中完成，不声称独立 Agent、新上板或跨项目复验。

模型输出若以摘要形式呈现，会明确标注“输出摘要”；只有确实逐字保留的内容才称为原始回答。自我纠错指可观察的“初始判断—反馈—修正—验证”，不指模型内部思维过程。

## 数字与结论口径

- 资源、时序、延迟和精度数字必须能回指工程材料，并同时保留测试条件。
- 综合或实现通过不等于上板正确；局部候选结果不等于整机结果；开发测试集不等于未见盲测。
- 不把不同计时边界拼接成加速比，不把典型耗时改善写成尾部或实时保证。
- 外部模型、运行时、生成代码、IP、文档和方法保持其来源与授权边界；本材料包主张的是项目适配、流程设计、验证组织与 Skill 沉淀。
